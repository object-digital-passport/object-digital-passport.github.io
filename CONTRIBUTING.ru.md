# Как вносить вклад в эталонный сайт

*Перевод справочно. Оригинал — только на английском: [`CONTRIBUTING.md`](CONTRIBUTING.md). При расхождении верен английский.*

Этот репозиторий — **одна реализация** [Object Digital
Passport](https://github.com/object-digital-passport/specifications), а не стандарт. Это различие
решает, куда относится ваш вклад, поэтому с него и надо начать.

## В какой репозиторий это относится?

| Если речь про… | Заводите |
|---|---|
| Что паспорт **есть**, что проверка **обязана** проверять, схему, контракты | **[репозиторий протокола](https://github.com/object-digital-passport/specifications/issues)** |
| Как этот сайт **выглядит** или **работает** — страницы, формулировки, вёрстка, баги браузера, переводы | **сюда** |

Полезная проверка: если менять пришлось бы и другой реализации — это вопрос протокола. Если этот
сайт может починить сам и остаться соответствующим — это сюда.

Поведение в сообществе регулируется [Кодексом
поведения](https://github.com/object-digital-passport/specifications/blob/main/docs/CODE_OF_CONDUCT.md)
из репозитория протокола, который действует в обоих репозиториях.

## Язык

**Задачи и pull request пишутся по-английски**, чтобы все в сообществе читали одну ветку
обсуждения. Сам интерфейс двуязычный — см. ниже.

## Безопасность

**Не** публикуйте пригодные к эксплуатации подробности в открытой задаче. Следуйте [политике
безопасности](https://github.com/object-digital-passport/specifications/blob/main/docs/SECURITY.md)
репозитория протокола; она покрывает и этот репозиторий.

## Запустить локально

Ни шага сборки, ни сервера — страницы статические и говорят с цепью из браузера.

```bash
TMP=$(mktemp -d) && cp -r frontend/. "$TMP/" && cp -r backend "$TMP/backend" && cd "$TMP" && python3 -m http.server 8080
# → http://127.0.0.1:8080/verify.html
```

## Что где лежит

| Путь | Содержит |
|---|---|
| `frontend/` | Страницы, CSS и скрипты интерфейса |
| `frontend/localization/{en,ru}/` | Каждую строку, которую показывает интерфейс |
| `backend/` | Код, который говорит с реестром со страницы, — помощники ABI, бандл WalletConnect, `registry-config.json` |
| `frontend/e2e/` | Дымовые тесты Playwright |

## Переводы

Строки интерфейса лежат в `frontend/localization/<язык>/*.json`. Есть английский и русский.

**Исправить или улучшить существующую строку — это чистое изменение данных:** правите JSON и
больше ничего. Пропущенный ключ откатывается к английской строке, а не отрисовывается пустым,
потому что `odp-i18n.js` накладывает перевод поверх английского набора и пропускает пустые
значения. Поэтому частичный перевод пригоден к работе, и это разумный первый pull request.

**Добавление третьего языка — пока не изменение данных.** `frontend/js/odp-i18n.js` зашивает `ru`
как единственный неанглийский язык — в списке языков, в трёх путях загрузки и в атрибуте `lang`,
который он выставляет на `<html>`. Добавить немецкий означает обобщить это до выбранного языка.
Заведите задачу до начала работы; этот рефакторинг стоит сделать один раз и как следует.

**Документация тоже переводится, и это проверяет CI.** У каждого документа этого репозитория есть
русская версия либо записанная причина, почему её нет; запись ведётся в
[`docs/TRANSLATIONS.md`](docs/TRANSLATIONS.md) и проверяется заданием `Translation parity`.
Добавили документ — добавьте строку; изменили документ — проверьте его перевод.

Переводы **справочные**. Нормативный текст —
[`SPEC.md`](https://github.com/object-digital-passport/specifications/blob/main/SPEC.md),
по-английски; если перевод и спецификация расходятся, права спецификация, а перевод — ошибка.

## Pull request

1. Ответвитесь от `main` с говорящим именем: `fix/verify-mobile-layout`, `i18n/add-german`.
2. Держите коммиты сфокусированными и следуйте стилю файла, который правите.
3. Прогоните тесты ниже до открытия pull request.
4. Открывайте pull request в `main`. CI запускает те же четыре задания, и все обязаны пройти.

```bash
cd frontend/e2e && npm install && npx playwright test    # дымовые тесты
node backend/test/odp-contract-0.7.test.mjs              # модульные тесты слоя чтения, из корня репозитория
```

У `backend` нет `npm test`: его скрипт `test` — стандартная заглушка npm, которая завершается с
кодом 1. Тесты слоя чтения — обычный скрипт Node, запускается ровно так, как в CI выше.

`main` защищена: принимает только pull request, и четыре задания CI обязательны. См.
[`.github/BRANCH_PROTECTION.md`](.github/BRANCH_PROTECTION.md).

## Один файл сгенерирован

`backend/js/odp-wallet-wc.bundle.js` — вывод сборки, закоммиченный потому, что при деплое шага
сборки нет. Не правьте его руками: следующий `npm run build:wc` в `backend/` перетрёт изменение.

## Не только код

Формулировки, визуальный дизайн, доступность и вычитка переводов нужны не меньше патчей. Если вы
проверили этим сайтом настоящую вещь и что-то вас запутало — это баг-репорт, который стоит завести.
